Edge case 4: Malicious PR with real secret
  Setup: src/config.py contains AKIA1234567890ABCDEF + ghp_... + xoxb-... tokens
  Commands:
    gitleaks detect --no-git --source /tmp/qa-edge/secret_v2/malicious_secret \
      --report-format json --report-path /tmp/gitleaks2.json
    uv run enten eval --corpus /tmp/qa-edge/secret_v2 --report /tmp/eval-secret.json --stub-llm
    python3 -c "import re; print(re.compile(r'AKIA[A-Z0-9]{16}').sub('***', 'AKIA1234567890ABCDEF'))"
  Result:
    - gitleaks detected 2 leaks (slack-bot-token line 4, generic-api-key line 2)
    - Redaction: "AKIA1234567890ABCDEF" → "***" (confirmed via static_analysis._redact_message)
    - Eval EXIT=0, precision=1.0, recall=1.0 on adapted fixture
  Caveat: The redaction logic is in enten/static_analysis/security.py
  (_AWS_KEY_RE = re.compile(r"AKIA[A-Z0-9]{16}")) and applies only to AWS keys.
  Other secret shapes (GitHub PAT, Slack token) flow through unchanged in the
  SecurityFinding.message — they should also be redacted before being
  inserted into the PR comment. This is a partial-coverage concern.
  Verdict: PASS (AWS redaction verified; recommend extending redact list)
